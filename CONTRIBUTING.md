# Contributing to StudySync

Thanks for taking an interest in StudySync!

This repository is being maintained to organize project documentation and demonstrate good software engineering and version control practices.

## Working on the Project

Before making changes, make sure you are working on the correct branch.

### Branching Guidelines

We follow a simple branching structure:

- `main` – Stable version of the repository.
- `develop` – Main development branch.
- `feature/` – Used for new features or documentation updates.
- `bugfix/` – Used for fixing existing issues.

### Commit Guidelines

Keep commit messages short and meaningful. Some examples:

- Add project documentation
- Update software requirements
- Fix formatting in README

### Pull Request Guidelines

Before merging changes:

1. Create a feature branch from develop.
2. Make the required changes.
3. Commit and push your changes.
4. Open a Pull Request against develop.
5. Review the changed files.
6. Merge the Pull Request after the review process.

## General Guidelines

- Keep documentation clear and easy to understand.
- Avoid unnecessary changes to existing files.
- Use meaningful file and branch names.
- Review contributions before merging.

*Good collaboration starts with clear communication and organized work.*
